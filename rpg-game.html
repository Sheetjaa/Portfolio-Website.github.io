2850 Final Project RPG Game

🎮 Game Development & C Programming 📅 Capstone Project

Project Overview

The 2850 Final Project RPG Game is a text-based dungeon exploration game developed as a capstone project for an upper-level computer science course. This project demonstrates fundamental game design principles, data structure implementation, and interactive state management through a fully functional RPG featuring room navigation, item collection, and inventory management systems.

Game Concept

Players explore a 3x3 grid of interconnected rooms within an ancient temple, searching for the legendary Lost Relic. Each room contains unique descriptions, collectible items, and hazards. The game tracks player health, inventory, and score as they navigate through the dungeon, collect treasures, and ultimately attempt to escape with the Lost Relic.

Personal Contributions: Core Game Systems

Room Navigation System

I implemented the directional navigation system that allows players to move between interconnected rooms. The system validates movement commands and prevents invalid transitions:

void movePlayer(char direction) {
    int nextRoom = -1;
    
    switch (direction) {
        case 'n':
            nextRoom = rooms[currentRoomIndex].north;
            break;
        case 's':
            nextRoom = rooms[currentRoomIndex].south;
            break;
        case 'e':
            nextRoom = rooms[currentRoomIndex].east;
            break;
        case 'w':
            nextRoom = rooms[currentRoomIndex].west;
            break;
    }
    
    if (nextRoom == -1) {
        printf("You cannot go that way.\n");
        return;
    }
    
    currentRoomIndex = nextRoom;
    look();  /* Display new room description */
}

This implementation ensures fluid navigation boundaries where players receive immediate feedback when attempting invalid moves, and successfully transitioning to new rooms automatically triggers a room description display.

Item Collection Mechanics

I designed and implemented the item collection system that allows players to interact with items found throughout the dungeon:

void takeItem(void) {
    if (strlen(rooms[currentRoomIndex].item) == 0) {
        printf("There is nothing to take here.\n");
        return;
    }
    
    if (inventoryCount >= MAX_INVENTORY_ITEMS) {
        printf("Your inventory is full!\n");
        return;
    }
    
    strcpy(inventory[inventoryCount].name, 
           rooms[currentRoomIndex].item);
    inventory[inventoryCount].quantity = 1;
    inventoryCount++;
    
    printf("You took: %s\n", rooms[currentRoomIndex].item);
    strcpy(rooms[currentRoomIndex].item, "");  /* Clear room */
}

The item system includes inventory capacity constraints, preventing players from collecting more than 10 items simultaneously, and one-time pickup mechanics where items are removed from rooms once collected.

Inventory Management

I developed a comprehensive inventory system that tracks collected items and allows players to review their belongings:

void displayInventory(void) {
    if (inventoryCount == 0) {
        printf("Your inventory is empty.\n");
        return;
    }
    
    printf("\n=== Inventory ===\n");
    for (int i = 0; i < inventoryCount; i++) {
        printf("%d. %s (x%d)\n", 
               i + 1, 
               inventory[i].name, 
               inventory[i].quantity);
    }
    printf("================\n\n");
}

The inventory system provides clear item enumeration with visual formatting and quantity tracking for stackable items, giving players complete visibility into their collected treasures.

Game Mechanics

Player State Management

The game tracks multiple player variables to determine current status:

  • Health: Starting at 100 HP, modified by environmental hazards
  • Score: Earned through treasure collection (10 points per item)
  • Current Location: Real-time tracking of player position in dungeon
  • Inventory: Dynamic list of collected items

Win/Lose Conditions

The game features clear victory and defeat states:

  • Win: Collect the Lost Relic from the Inner Sanctum
  • Lose: Health drops to 0 or below (defeated by temple hazards)

Command System

Players interact with the game through an intuitive command interface:

  • n/s/e/w - Navigate in cardinal directions
  • look - Examine current room description and available items
  • take - Collect items in the current room
  • inventory - Display collected items
  • help - Show available commands
  • quit - Exit the game
